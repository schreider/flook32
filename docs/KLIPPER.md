### Принцип работы модуля

Плагин `flook32.py` и прошивка `flook32.ino` спроектированы так, чтобы **передаваемая температура никогда не могла вызвать падение Klipper**.

| Что делает плагин | Что НЕ делает плагин |
|------------------|---------------------|
| Передаёт показания датчика как есть | Не анализирует температуру |
| Выводит ошибки | Не принимает решений об остановке печати |
| Возвращает последнее валидное значение при потере связи | Не генерирует исключений |
| Продолжает работать даже если FLOOK32 недоступен | Не падает в ошибку по связи |

Вот исправленная часть про fallback:

### Почему Klipper не упадёт

1. **Нет критических проверок** — плагин не проверяет валидность температуры
2. **Fallback значения** — при потере связи возвращается последнее успешно полученное значение
3. **Отсутствие исключений** — любые ошибки перехватываются и логируются, но не прерывают работу
4. **Таймауты** — HTTP и WebSocket запросы имеют жёсткие таймауты

### Пример

Даже если FLOOK32 отключится или нагреватель выйдет за допустимые пределы:

```yaml
# Пример 1: перегрев воздуха — FLOOK32 сам отключил нагрев
# Входные данные (с FLOOK32)
airTemp: 85.0  # Перегрев воздуха, FLOOK32 отключил SSR, вентилятор 100%

# Выходные данные (в Klipper)
temperature: 85.0  # Плагин передаёт реальное значение, но нагрев уже отключён

# Klipper ПРОДОЛЖАЕТ печать — нагрев безопасно остановлен силами FLOOK32

# Пример 2: потеря связи — плагин возвращает последнее известное значение
# Входные данные (с FLOOK32)
airTemp: недоступен  # FLOOK32 отключился или потерял связь

# Выходные данные (в Klipper)
temperature: 25.0  # Возвращается хардкод значение

# Klipper ПРОДОЛЖАЕТ печать — паузы или аварийной остановки не происходит
```

### Отображение ошибок

Все ошибки FLOOK32 выводятся в консоль Klipper, но **не влияют на ход печати**:

```text
!! FLOOK32: КРИТИЧЕСКАЯ ОШИБКА [00:15:30]: Перегрев нагревателя! T=125.0°C
!! FLOOK32: КРИТИЧЕСКАЯ ОШИБКА [00:16:45]: Система заблокирована: Тройной перегрев нагревателя (3/3)
```

Печать продолжается, пользователь видит ошибку, но принтер не останавливается.

### Итог

Плагин работает как **пассивный датчик температуры**, а не как активная система защиты. Вся логика безопасности остаётся на стороне FLOOK32.

## 1. Установка модуля

### 1.1 Копирование файлов

Скопируйте файл `flook32.py` в директорию расширений Klipper:

```bash
cp flook32.py ~/klipper/klippy/extras/
```

Скопируйте файл `flook32.cfg` в папку с `printer.cfg`:

```bash
cp flook32.cfg ~/printer_data/config/
```

### 1.2 Установка WebSocket клиента (опционально)

Для получения данных датчкиков в реальном времени:

```bash
pip install websocket-client
```

## 2. Настройка printer.cfg

Добавьте в файл `printer.cfg`:

```ini
[include flook32.cfg]
```

### 2.1 Перезапуск Klipper

```bash
sudo systemctl restart klipper
```

## 3. Проверка работы

### 3.1 Логи Klipper

Проверьте, что плагин загрузился:

```bash
tail -f ~/klipper/logs/klippy.log
```
Вы должны увидеть:

```text
Loaded module 'flook32'
Found FLOOK32 at 192.168.1.100
```
### 3.2 Веб-интерфейс Mainsail / Fluidd

После настройки в интерфейсе Mainsail или Fluidd появится датчик `chamber` с текущей температурой воздуха.

### 3.3 GCODE команды

Стандартные команды `M141`/`M191` **не поддерживаются плагином напрямую**. Для их работы добавлены макросы-переопределения в `flook32.cfg`:

<details>
<summary>Почему макросы не вшиты в плагин?</summary>

Макросы `M141`/`M191` могут быть уже определены в среде пользователя на принтере. Плагин не навязывает жёсткую логику — вы можете написать их под свой конкретный случай, изменяя макросы на своё усмотрение.

</details>

| Команда | Описание | Реализация |
|---------|----------|------------|
| `M141 S60` | Установить цель 60°C | Через макрос → `FLOOK_SET S=60` |
| `M141 S0` | Выключить нагрев | Через макрос → `FLOOK_OFF` |
| `M191 S60` | Ждать достижения цели | Через макрос → `FLOOK_SET S=60` + `TEMPERATURE_WAIT` |

### 3.4 Интеграция в START_PRINT и END_PRINT

Для автоматической установки температуры камеры из слайсера и отключения нагрева по окончании печати необходимо добавить вызовы макросов `M141`/`M191` в системные макросы принтера `START_PRINT` и `END_PRINT`.

Универсальной инструкции не существует — структура этих макросов зависит от конкретного принтера, прошивки и пользовательских модификаций. Ниже приведён минимальный пример, который можно адаптировать под свою конфигурацию:

**START_PRINT (фрагмент):**
```
[gcode_macro START_PRINT]
gcode:
    {% set CHAMBER = params.CHAMBER|default(0)|float %}
    # ... разогрев стола, парковка, прогрев сопла ...
    M141 S{CHAMBER}        ; Установить температуру камеры из слайсера
    M191 S{CHAMBER}         ; Ждать достижения цели (опционально)
    # ... старт печати ...
```

**END_PRINT (фрагмент):**
```
[gcode_macro END_PRINT]
gcode:
    M141 S0                 ; Выключить нагрев камеры
    # ... парковка, охлаждение, отключение моторов ...
```

## 4. Автоотключение по Moonraker

### Зачем это нужно?

Если вы часто печатаете несколько моделей подряд и не хотите, чтобы камера остывала между печатями — не добавляйте команду `M141 S0` в макрос `END_PRINT`. Вместо этого используйте автоотключение по Moonraker: FLOOK32 будет отслеживать статус печати и отключит нагрев только через заданное время после её завершения.

Это также полезно, если по какой-то причине вы не можете использовать плагин Klipper и не можете использовать макросы с `wget` из `shell_command` — встроенная функция автоотключения работает независимо от плагина, напрямую через HTTP-запросы к Moonraker API.

### 4.1 Настройка в веб-интерфейсе

1. Откройте веб-интерфейс FLOOK32
2. Перейдите в **Настройки → Общие**
3. В разделе **Moonraker автоотключение**:
   - Установите чекбокс **Включить автоотключение после печати**
   - Выберите время ожидания (5-120 минут)

### 4.2 Принцип работы

1. FLOOK32 опрашивает Moonraker API
2. Отслеживает статус печати: `printing` → `complete`/`error`
3. После завершения печати ждёт N минут
4. Выключает нагрев камеры

### 4.3 Проверка связи с Moonraker

Статус Moonraker отображается в веб-интерфейсе FLOOK32 на главной странице, в блоке Klipper.

| Индикатор | Значение |
|-----------|----------|
| 🌙 Автоотключение через N мин после печати | Moonraker подключён, автоотключение настроено и работает |
| 🌙 Moonraker не подключён | Moonraker недоступен, автоотключение не работает |

## 5. Отправка конфигурации на ESP32

### Принцип работы

Плагин Klipper отправляет на ESP32 **только те параметры, которые явно указаны в printer.cfg**. Это позволяет:

- Не затирать настройки по умолчанию на устройстве
- Изменять только нужные параметры

### Процесс отправки

1. При запуске плагин читает секцию `[temperature_sensor chamber]` в printer.cfg
2. Формирует JSON с указанными параметрами
3. Отправляет POST запрос на `http://[IP]/api/config`
4. ESP32 сравнивает и применяет только изменённые параметры

### Пример

**В printer.cfg указано:**

```ini
[temperature_sensor chamber]
sensor_type: flook32
flook_ip: 192.168.1.100
max_heater_temp: 105.0
fan_on_temp: 60.0
```

На ESP32 будет отправлено:

```json
{
  "maxHeaterTemp": 105.0,
  "fanOnTemp": 60.0
}
```
Параметры `criticalTemp`, `maxAirTemp`, `hysteresis` и остальные останутся как на устройстве.

### Какие параметры можно отправлять

Любые параметры из [полного списка](#полный-список-параметров).

### Проверка

После отправки конфигурации можно проверить:

```bash
FLOOK_CONFIG_GET
```
